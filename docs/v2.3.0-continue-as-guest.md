# v2.3.0 — Continue as Guest Checkout

**Date:** 2026-05-13

## Overview

Customers can now checkout without creating an account. When clicking **Checkout** in the cart, a modal appears offering two options:

- **Sign in with SSO** — existing Auth0 login flow (unchanged)
- **Continue as Guest** — proceeds directly to the checkout form without authentication

## UI Changes

### ShoppingCart (`/my-cart`)
- The login modal now shows two buttons: "Sign in with SSO" and "Continue as Guest"
- Selecting "Continue as Guest" sets `isGuest = true` in the Zustand auth store and navigates to `/shipping-address`

### AddressShipping (`/shipping-address`)
- Page guard updated: allows through if `isAuthenticated` OR `isGuest` is true
- Guest users see a banner: "Checking out as Guest — your order won't appear in 'My Orders'"
- An **Email Address** field is shown for guests (mandatory — email is needed to associate the order)
- Name field is **not** prefilled for guests (all fields blank)
- On submit, the guest API client (`GuestOrderAPIClient`) is used — no Authorization header is sent

### User Dropdown (Desktop + Mobile)
- **"My Orders"** menu item is hidden when `isGuest === true`

### Zustand Auth Store
- Added `isGuest: boolean` (default `false`) with `setIsGuest()` action

## API Changes

### New Guest Endpoints (no auth required)

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/orders/guest/create-payment-intent` | Create Stripe PaymentIntent for guest |
| `POST` | `/orders/guest` | Create order record for guest (email from shipping address) |

### `login_type` Field

Every order now records how the customer authenticated:

| Value | When |
|-------|------|
| `guest` | Customer checked out as guest |
| `google` | Auth0 social login via Google |
| `github` | Auth0 social login via GitHub |
| `facebook` | Auth0 social login via Facebook |
| `twitter` | Auth0 social login via Twitter |
| `microsoft` | Auth0 social login via Microsoft |
| `linkedin` | Auth0 social login via LinkedIn |
| `auth0` | Auth0 username/password |
| `sso` | Any other Auth0 connection |

The authenticated routes also pass `login_type` from the request payload (derived on the frontend from `auth0User.sub`).

### DB Migration

An idempotent migration (`migrate_add_login_type()`) runs on every API startup. It adds `login_type TEXT DEFAULT 'sso'` to the `orders` table if the column does not already exist. Existing orders get the default value `"sso"`.

## Admin Purchases Page

A new **"Login Type"** column appears in the purchases data table with color-coded badges:
- `guest` → yellow (`badge-warning`)
- other values → blue (`badge-info`)
